# 公司平面地图 v2：空间分析与接入

## 1. 权威来源和转换边界

空间依据 `/Users/hepingyu/Downloads/1203平面图.pdf`（单页 CAD 平面图）。渲染保存在 `assets/company-office-floorplan-v2/source-floorplan.png`，源 PDF SHA-256 记录在布局 JSON 和生成来源中。

旧暖木/青绿六工位图仅作**画风参考**。没有用旧生成地图替代真实平面图，也没有迁入旧仓库的19座、斜向移动或权限系统。

本版是公司户型的**游戏空间适配**，不是施工图或消防疏散图：保留房间相对位置、分组、门洞、通道和入口关系；为了容纳确认的192像素工位，调整了游戏间距。右下斜外墙、上沿斜窗改为直角阶梯。像素不能换算成施工毫米，门的主次及用途须现场确认。

## 3. 画风与生成方法

使用内置 imagegen 生成静态像素地图。输入明确分工：

1. `layout-guide.png`：正交墙体、门洞及空白办公区的结构约束。
2. `frontend/company-office/office-map-v1.webp`：暖木色、青绿和米色地砖的画风参考。
3. `media/workstation-reference.png`：已确认工位的画风 / 比例参考，禁止烘焙进背景。
4. `source-floorplan.png`：原公司 PDF 的邻接关系参考。

实际完整提示词：`assets/company-office-floorplan-v2/map-prompt.txt`；调用参数：`generation-request.json`。原始生成图1070×1470原样保存；以最近邻规范到2048×2816、无损WebP进入运行目录。生成宽高比与目标宽高比差约0.085%，不是响应式时动态拉伸。

`layout-guide.svg` / `floorplan-analysis.svg` 是程序生成的**原生SVG结构分析图**，不是伪装成AI像素美术的替代地图。结构脚本可重建布局与分析图，但不会重新生成背景；墙体大改后应重新出图并验看。

## 4. 分层和动画适配

```text
2048×2816 新地图背景（无角色、无办公桌 / 椅 / 显示器 / 键盘）
  ├─ 静态会议家具、柜子、打印设备和机柜
  └─ 36个工位组合：椅子后景 → 可替换角色 → 桌 / 显示器 / 键盘前景
```

- 工位仍192×192、scale=1、direction=down，不能独立拖动某一家具层造成错位。
- 主角 `desk-26`，位置 `[1420,1660]`。六状态都坐在这个工位。
- 原橘猫母版、工位、四套脸部图集和 `seated-compositor.mjs` 原样复用；冻结源的21文件哈希未改变。
- 每套12帧、12fps；工作 / 等待每5秒一轮，睡觉每3秒一轮，迷糊旋涡眼连续循环。
- 不画手、不播放敲键盘动作，身体 / 耳朵 / 尾巴 / 家具固定，只动脸部表情。
- `working`只为表情动作名，不新增API业务状态。仍是idle、writing、researching、executing、syncing、error。
- 换角色沿用 `officeRuntime.replaceCharacter(characterConfig, {baseUrl})`，新角色目录无需复制家具。角色必须有自己的固定坐姿及锚点，不可用任意站立PNG顶替。
- 四方向A/B仍是确认的方向模板，不伪造完整12帧行走；本地图没有新接入未完成的行走循环。

## 5. 真主页面与使用方式

运行的仍是 Flask `/` 返回的 `frontend/index.html`，不是独立假预览。

- 默认 `/`：本版公司平面地图。
- `/?view=workstation`：直接看橘猫工位近景。
- `/?scene=v1`：回到上一版暖木六工位地图。
- `/?scene=legacy`：原雪山木屋，资源未覆盖。

顶部“公司全图 / 橘猫工位”按钮只切相机，不重新生成图或移动工位。全图模式自动适配纵向户型，近景看清表情和桌 / 显示器对齐。相机世界尺寸与页面画布尺寸分离；缩放后拖动按zoom换算世界坐标。手机默认不拦截页面滚动，只有显式打开“移动视野”才接管上下左右拖动。

入口文件：

| 改动 | 位置 |
|---|---|
| 户型 / 房间 / 工位 / 主工位 / 访客点 | `frontend/company-office/map-layout.json` |
| 地图美术 | `frontend/company-office/office-map-floorplan-v2.webp` |
| 几何校验、组合器接入、换角、相机 | `frontend/company-office/runtime.mjs` |
| 两个视图按钮、手机布局、原主页面hook | `frontend/index.html` |
| 原家具 / 角色规格及六状态映射 | `frontend/company-office/office-assets.json`，本轮不改 |
| 重建空间分析 / 布局 | `node scripts/build_company_floorplan.mjs`，输出资产目录；确认后再复制布局到运行目录 |
| 自动测试 | `node scripts/test_company_office.mjs` |

默认运行配置仍使用原生产数据路径。本地19000预览显式设置 `STAR_OFFICE_DATA_DIR=.local/company-office-preview`，仅监听loopback。没有部署到远端，没有覆盖真实生产业务数据，没有停止其他素材预览。

## 6. 验收范围

具体记录见 `assets/company-office-floorplan-v2/` 中的QA JSON和截图。

- 布局校验：33+3个工位；分组8、8、8、6、3；8个命名空间；全部down、原尺寸；重复 / 叠墙 / 出界 / 压主通道 / 占门洞拒绝。
- 六状态真实`/set_state`写入和`/status`读回均200，并进入主页面的`applyVisualState` / runtime。
- 72帧实Canvas验证：每个动作12张不同帧，脸部区域外变化像素为0，家具世界坐标不变。
- 重复状态不重置时钟；已确认角色通过接口重载后，家具和业务状态不变。
- 桌面 / 手机两个视图、访客点和回退版本另做实浏览器验收。

程序验收与用户的画风确认不同：本版已经可运行，但新地图视觉仍等待用户查看；不宣称精确CAD复刻、真实手机实机验收或远端生产部署完成。
