# 橘猫动画：简化为提示词生成

按用户本轮要求：停止修绘旧候选，取消四关键帧、逐针补丁、骨骼和多轮评分的默认流程；保留程序所需的简单静态工位/独立角色图层。旧文件保留，不替换生产素材。

## 新流程

**工位单独静态绘制一次；同一母版＋固定工位几何参考＋一个动作/一个朝向提示词 → 一次生成角色-only 12帧 → 等格裁切 → 程序组合验看。**

- 上下左右**各12帧**，共48帧。
- 每套动作独立成图，4列×3行、按行播放、真实透明背景。
- 新素材预览默认12fps（12帧约1秒）。这是新的素材制作规格，不是声称原版所有动画都只有12帧。
- 行走/待命/告警目标单格96×96；办公角色与工位共享192×192坐标。生成图可更大，后续按同一尺度整理，不让模型逐针输出/修改。
- 一次出图不合格则先展示，不默认反复改图或拼接失败稿。

## 四向与工位约束

- 所有角色只允许沿地图十字轴：上、下、左、右。禁止斜向、45°、三分之四视角或旋转镜头。
- 办公默认向下，角色正对画面坐在工位桌后；桌椅、键盘和显示器与坐姿同轴，不斜坐。
- 工位方向若向上则画背面，向左/右则画对应侧面；每套12帧固定同一方向。只有需要不同朝向的工位才另生成，不默认把所有状态乘以四。
- 办公/同步动作不画家具：静态椅子后景→独立角色→桌子/键盘/显示器前景。桌与屏同一静态PNG、程序不独立移动；家具不进入12帧图集。换角色只切角色素材及一次性的poseAnchor/scale配置。
- 优先附当前地图的实际工位图；没有则注明概念稿，不能声称已匹配地图。
- 行走仍只画角色。idle保留休息待命用途，error保留告警区域用途，不强制附新办公工位。
- 接入时若地图已有家具，应复用，不把候选组合图又叠出一套桌椅电脑。这里不改生产图层。

## 状态资源

业务状态遵循系统的六个state，不增加接口：

| state | 默认动画素材 | 含义 |
| --- | --- | --- |
| idle | idle | 待命、呼吸、眨眼 |
| writing | working | 整理文档，共用办公动作 |
| researching | working | 搜索信息，共用办公动作 |
| executing | working | 执行任务，共用办公动作，不是跑步 |
| syncing | syncing | 同步备份、专注等待 |
| error | error | 出错提醒、轻微反应 |

默认资源总数：**4方向 + 4状态视觉 = 8套，每套12帧，共96帧**。writing/researching/executing共用办公动作符合当前原版主角色的共享关系。若希望六业务状态各有独立表现，现已备好writing/researching/executing的可选独立提示词，届时共10套/120帧，不默认多做。

同步和错误的橘猫动作是新增素材设计。原版目前隐藏主角色并使用独立sync_anim/error_bug效果；后续接入时再处理显示，不在提示词制作阶段改它。

## 可复用Skill

项目内：`.agents/skills/star-office-character-animation/SKILL.md`。

调用示例：

- 使用 `$star-office-character-animation`，生成橘猫向下行走的12帧透明动画。
- 使用 `$star-office-character-animation`，生成橘猫上下左右各12帧的四张动画图。
- 使用 `$star-office-character-animation`，按原版共用关系生成idle/working/syncing/error四套状态动画，各12帧；办公和同步正对画面坐在同轴工位上。
- 使用 `$star-office-character-animation`，将writing/researching/executing拆成独立动作，均正对画面坐在同一工位上，各12帧。

完整提示词位于Skill的 `references/prompt-library.md`。`scripts/make_prompt.py`只拼接/输出提示词；需要出图时才调用内置imagegen。

**初始方案阶段仅建立Skill、母版和提示词映射；后续候选生成与当前验收状态如下。状态API和生产播放器仍未修改。**
