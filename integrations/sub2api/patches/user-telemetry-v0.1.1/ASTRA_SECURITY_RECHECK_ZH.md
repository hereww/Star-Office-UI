# GPT-6 Astra 安全审计及复核

日期：2026-10-04。只读审计；开发由四个 GPT-6.1 Sol 子代理分别处理签名打包、SDK/生命周期、reader、runtime/UI，主代理集成。

## 稳定范围

审计覆盖契约、独立消费凭据 handler/store/迁移及管理/外部路由；不将该静态审计冒充整个 runtime 的安全认证。真实受管进程、数据库和浏览器验收另见 ACCEPTANCE_ZH.md。

## 初审与修复

初审没有 P0/P1，发现三个 P2：签发时空用户范围默认扩大；认证查库前没有并发/频率预算；凭据列表 LIMIT 1000 静默隐藏旧凭据。另发现空 store 测试可以导致普通凭据拒绝的假通过。

已修复：

1. 签发必须显式1..500用户ID，缺失/null/空列表拒绝；单一JSON对象及完整尾部校验。
2. 查库前每宿主20/s、burst40、16在途预算；实际导出仍8并发/5秒。
3. 凭据降序keyset分页，page_size+1检测next_cursor；额外条目不跳过。真实PG覆盖1002凭据、11页并能盘点最早凭据。
4. 非nil store stub断言非法凭据0次认证查询；补401/503、scope、burst/并发、分页参数测试。

Astra修复后只读复核：此前三项P2和假通过问题全部解决，同范围未发现残留必须修复的P0/P1/P2；复跑9个定向单测通过。后续集成另补撤销存储失败明确503、不伪装404，以及HTTP默认时区/页大小取保存配置。

## 未越过的边界

- 管理路由保留原adminAuth，创建/撤销保留原step-up开关语义，不宣称强制始终启用2FA。
- 凭据只一次性返回给已认证签发管理员，数据库只存SHA-256；不能宣称任何管理员JS都永远无法读取签发响应。插件iframe本身不获得管理员/消费端秘密。
- 外部输出取签发范围与当前批准范围交集；角色主体是user_id，Keys仅为嵌套元数据。
- 只读是业务/RPC范围，不是OS沙箱；原并发读取会清理过期槽位。
- Astra没有向真实生产系统签发凭据、造数据或压力测试，未部署或修改动画仓库。
